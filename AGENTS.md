# Project architecture rules
- Keep Ultra history, confirmations and recovery isolated in Ultra-only helpers and components, and breaker pause/probe state in a service-only atomic database function shared by health reads and the proxy before charges; bound new calls to two seconds and never mutate submission payloads. // ULTRA-SMART-PREVENT-1024
- Keep Metro first-screen presentation behind the optional GoLander metroFirstScreen prop, enabled only on Metro ad routes, so default carrier DOM and existing validation/navigation remain unchanged. // METRO-FIRSTSCREEN-1023b
- Keep Cricket bill-page copy and FAQs in the existing billCarrierSeo content source and existing static head renderer so visible answers match one FAQPage without adding scripts or changing shared payment logic. // BILLPAY-CRICKET-1023
- Keep Simple Mobile legacy ad-page aliases on the existing AliasRedirect component so English/Spanish destinations preserve search parameters and hashes without adding prerender shells. // SIMPLE-PUSH-1023
- Keep Ultra LoadText display overrides in the carrier-aware pure picker, called only in checkout refund presentation, and plan labels in the display-only content helper; retain receipt fallback and untouched payment values and recovery handlers. // ULTRA-MSG-1024
- Keep T-Mobile retry gating in a pure fail-open helper with injected lookup/events and customer wording in a frontend-only module so blocked attempts never reach payment or transaction logging. // TMO-LOOKUP-1020
- Keep SMS legal copy in an import-free shared content source for runtime and static rendering, and SMS consent in the existing best-effort tracking queue outside payment validation and payloads. // SMS-34332-1020
- Keep decline classification and analytics button mappings in the shared declineRecovery helper, and post decline events in an independent funnel batch so analytics failures cannot affect payments or legacy logging. // DECLINE-REJECTED-1018
- Keep carrier payment guides in the shared howToPay content source and existing renderers so runtime text and prerendered FAQ schemas match. // AEO-12-TRACFONE-1018
- Keep Verizon prepaid history gating in a pure shared edge-function helper with injected lookup/audit dependencies so fail-open behavior is unit-testable.
- Keep Verizon customer wording in a frontend-only shared module using relative imports from prerendered content so runtime and static notes match.
- Keep Klarna analytics dimensions and per-offer dedupe isolated from existing funnel events, with separate edge inserts, so logging failures cannot affect legacy analytics or payments.
- Keep outage tracking retries and phone/amount locks in browser helpers, and logging races and isolate dedupe in pure edge helpers, so outage behavior is testable without modifying payment requests.
- Keep carrier refund retry policy and browser-only context in a pure frontend helper, and retry analytics in an independent edge batch, so retries cannot bypass payment guards or disrupt legacy logging. // REFUND-RETRY-1018
- Keep carrier email token handling in one once-ready hook with a current callback ref so carrier pages share resolution and cleanup without overwriting typed input. // ST-PREFILL-1018
- Keep late-refund receipt retries in a shared RefundRetryButtons component over the pure refundRetry helpers, and the retry cap as a fail-open gate before any log/dedupe/CellPay call, so receipt and checkout retries stay identical and the cap can never block a normal order. // REFUND-RETRY-LATE-1018
- Keep checkout transaction timeout, outcome-unknown classification and attempt logging in a pure checkoutTimeout helper, passed to apiWrapper only via optional call options, so other proxy callers keep default behavior. // CHECKOUT-TIMEOUT-1023
- Keep refill-prevention checks in pure fail-open helpers with separate switches and storage for mismatch/discontinued blocks; share the dead list across plan lists and saved carts, and check it in the bounded cached proxy plan guard, without changing payment payloads or refund-card retry logic. // REFILL-PREVENT-1024 // LYCA-SKU-FIX-1024
- Keep Ultra MDN plans (source B) separate from carriers/view plans: the proxy route/cache and MDN plan guard live in cellpay-proxy, and barcode is added only through apiWrapper's applyUltraMdn when the checkout phone and plan match the picked MDN plan, so A-plan orders stay unchanged. // ULTRA-MDN-1029
